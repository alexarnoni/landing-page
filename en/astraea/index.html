Problem

Astraea brings public NASA data on near-Earth asteroids and solar events into one pipeline and exposes it through a public API. On top of that data sits a machine learning model, and that model had to be rebuilt.

The previous version (1.0.0) predicted risk_label, which is computed by a rule over the same columns the model received. The high accuracy only showed that it had relearned the rule. The target is now NASA's is_potentially_hazardous flag, using only relative velocity, approach distance in lunar distances and H magnitude, with the flag itself not used as an input (3 variables).

Data

Ingestion is daily, through NASA NeoWs and DONKI. Transformation uses dbt Core in staging and mart layers, and PostgreSQL is the central storage.

For the model: 2,083 close approaches of 1,822 asteroids. Both positive counts appear in the model report and measure different things: 189 approaches with a positive flag, which correspond to 180 asteroids (the same asteroid can have more than one approach).

Decisions

The displayed risk is a rule, not the model

The displayed risk is the rule-based risk_score, my own heuristic with thresholds I chose (20 km/s, 1,000,000 km, 0.5 km), not a NASA methodology. The score adds 3 points if the asteroid is a PHA, 2 if velocity is above 20 km/s, 2 if distance is below 1,000,000 km and 1 if diameter is above 0.5 km. With 6 points or more the risk is high; with 3 or more, medium.

The model exposes something else: the probability that NASA's PHA flag is positive.

Validation

StratifiedGroupKFold with 5 folds, grouped by asteroid, so the same asteroid never appears in both training and test. Plus a temporal evaluation, training on older dates and testing on newer ones (cutoff on July 12, 2026).

API

9 endpoints: 7 data endpoints under the /v1 prefix, plus / and /health. Rate limit of 60 requests per minute per IP. Documentation at astraea-api.alexarnoni.com/docs.

At the default 0.5 threshold, recall is 0.44: the model misses more than half of the PHAs.

Comparison with a simple rule

The model ranks asteroids better than magnitude alone under grouped validation (PR-AUC 0.64 versus 0.36, on the out-of-sample probabilities of the 5 folds pooled; in the table, 0.65 is the mean across folds). At high recall, the advantage over the simple cutoff H <= 22 is small (precision 0.405 versus 0.389, within noise). The H <= 22 rule alone has recall 0.995 and precision 0.39. This is an exploratory analysis run after seeing the first results, outside the original plan. The numbers in this comparison are in the model report.

Limitations

  • MOID (minimum orbit intersection distance, 0.05 AU threshold), which defines the flag together with H, is not among the model's variables.
  • The distance used is that of one specific approach, not a stable property of the asteroid.
  • H dominates the model. The estimated diameter was dropped because it is an exact function of H.
  • There are few positive asteroids (180).
  • F1 drops from 0.52 to 0.39 on the temporal split, and the data cannot separate temporal drift from variance (43 positives in the test set). Details in the report.
